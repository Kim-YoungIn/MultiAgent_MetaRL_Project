# Open Questions

## 다음 연구 계약에서 먼저 결정할 사항 (D-018)

첫 문법·manifest·4조건 비교는 D-019/D-020으로 구현·실행했다. 아래 항목들은 그 범위의 후속 확장 질문이다.
현재 우선 해석 과제는 약한 neural 학습과 단순 repeat/copy/Q의 차이, 생성 분포의 공통 일치관계 bias,
구조 유사성·노출량과 다양성의 효과를 어떻게 분리할지다. 모든 국소 진단을 다시 선행 관문으로 두지 않는다.

- 통제된 Generator의 최소 문법·조합·파라미터 범위와 대칭 공통 F의 유지 범위는 무엇인가?
- 표현/정확한 텐서/행동 재명명 후 중복을 어떻게 구분하며 구조·보상 거리 후보는 어떻게 정의할 것인가?
- 규칙과 상대 변화가 좋은 대응을 바꾸는 MA 게임군, 도달 가능한 정보 활용 기준,
  능동 exploration을 요구하는 하위집합을 어떻게 구성할 것인가?
- 학습/평가 manifest, 난이도·유사성·노출량 통제와 H1/H2의 효과·불확실성 기준은 무엇인가?
- 공통 학습 정책/참조 모델, seed 수, 예산·허용 튜닝과 종료 조건을 무엇으로 사전 고정할 것인가?
- 새 상대의 메모리는 episode/trial 중 어디에서 초기화하는가? 현재 collector는 상대를 episode마다,
  learner hidden을 trial마다 초기화한다. 이 비대칭이 새 연구 조건에 적합한지 결정해야 한다.

추가 기능 진단의 성공은 위 설계 작업의 선행 조건이 아니다.

## 기존 미해결 항목

- 규칙의 변경은 task/trial 경계에서만 일어나는가, 아니면 하나의 trial 중에도 일어나는가?
- 현재 평가는 순수 hidden state 갱신만 허용한다. 후속 연구에서 테스트 시 추가 학습과 비교할 것인가?
- Independent Co-training을 필수 baseline으로 할 것인가, 고정 상대를 먼저 사용할 것인가?
- Exploration은 단일 policy에서 암묵적으로 학습하게 할 것인가, 목적함수 또는 정책을 분리할 것인가?
- 논리적으로 생성된 규칙의 난이도·식별 가능성·전략적 다양성을 어떻게 통제할 것인가? 무작위 텐서는 현재 기본 생성에서 제외하며 비교군 채택은 별도 결정이다.
- 어떤 성능 지표가 실제 적응과 초기 일반화를 구분하는가?
- 연구용 episode/trial 길이는 얼마로 할 것인가? 현재 recurrent baseline은 trial 내 동일 task·hidden 유지, trial 시작 초기화. 단일 episode runner는 매번 상태 초기화한다.
- 현재 PPO는 유한 trial의 최종 bootstrap 0. 계속되는 task나 rollout 절단을 도입할 경우 bootstrap·TBPTT를 어떻게 처리할 것인가?
- shared candidate scorer는 동일 weights의 n=3/4/5 실행을 지원한다. n 간 학습 일반화와 행동 라벨 정규화 가정은 어떻게 평가할 것인가?
- 40-update 단일 seed의 정체를 고정/가변 과제와 seed3개로 분리 진단했다.
  후속 비교의 학습량·최적화·기억 사용 통제를 어떻게 구성할 것인가?
- 분리 진단(seed3개)에서 고정 target0/2는 높은 보상, target1은 Random 수준이었다.
  번호 교환 대조에서는 내부 번호1이 정체됐고 초기 mean actor gradient의 상쇄를 관찰했다.
  비서열적 공유 action-state 구조의 순열 대칭성을 검증했다. nH 기억 용량 변화와 기존 인코딩 효과를 어떻게 분리할 것인가?
  가변120update의 작은 수치 상승과 즉시 지도학습 fit을 유용한 trial 적응으로 연결하려면 무엇을 통제해야 하는가?
- 새 3가족 파일럿에서 informed 기준은 높은 보상과 기억 이득을 보였으나 신경망40updates는 미흡했다.
  조건부 보상 활용, policy/value 공유 최적화, 데이터 예산 중 병목을 어떻게 분리할 것인가?
  상대 과제의 단순 반복 점수0.5를 넘어 실제 상대 식별을 확인할 지표/대조를 어떻게 구성할 것인가?
- 최소 체류 길이 후 확률적 전환을 채택한다면 상태/이전 보상/hidden state 유지 및 전환 신호는 어떻게 처리할 것인가?

이 목록은 결정을 요구하는 검토 항목이며, 질문이 적혀 있다는 이유만으로 현재 Toy Model 구현을 막지 않는다.
