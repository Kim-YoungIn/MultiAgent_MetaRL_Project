# 패치 검토와 실행 경로 선택

로컬 패치가 추가한 코드는 posterior 보상·불확실성을 받는 GRU, 즉시 보상을 예측하는 Student, 업데이트 이후 절대 보상의 IPS 대리 목적을 사용한다. 기존 CPU 및 CUDA 개발 결과와 중단된 Fast Exploration 원래 final 실행은 별도 기록이다. 새 24블록 실행은 현재 요구한 예산으로 시작했다.

| 확인한 항목 | 조치 |
|---|---|
| 평가 게임 수 표기가 리셋 수만큼 복제한 시드 수를 가리켰고 그 시드가 매번 다른 규칙도 생성했다 | 규칙 시드 128개와 별도 초기화 시드 256개를 분리했다. 같은 규칙에 두 리셋을 적용한다. |
| 탐색과 평가를 스칼라 환경 루프에서 매번 재생하고, 한 업데이트 안에서 매 게임 GRU를 개별 호출했다 | 기존 D-031의 rollout/배치 autograd 재생 구조를 따랐다. Teacher 입력과 Q 및 Student 상태를 배치화했다. 보상·전이 조건은 규칙별 절 순서를 유지한 벡터 연산으로 옮겼다. |
| 비교 정책마다 같은 규칙과 상대 예열을 다시 계산했다 | Learned와 Belief-Blind가 동일 배치를 공유한다. 평가 자연·통제 조건은 탐색을 공유하고 handoff 시 분기한다. |
| 결과 기록이 완성되지 않으면 블록 내부 학습을 처음부터 다시 시작했다 | 25업데이트마다 양쪽 optimizer와 sampler 상태를 저장한다. 블록 결과는 해시가 기록된 JSON을 마지막에 발행한다. |
| 초기 패치의 평가 그래프는 H=24 문구를 고정했다 | 실제 결과의 평가 길이를 이용한다. |
| 기존 문서는 CPU PyTorch 설치 예제와 CUDA 사용 환경을 함께 가리켰다 | 새 실행 문서에서 실제 사용 장치, wheel, 결정론적 CUDA 환경 설정을 따로 기록한다. |

## 측정 결과

같은 시드, 두 Teacher 각각 16업데이트×32게임, K=0/4/8/16/24, H=32로 비교했다. 학습은 기존 스칼라 CPU 27.45초, 배치 CPU 3.27초, CUDA 학습+CPU 추론 5.34초, CUDA 학습+CUDA 추론 5.74초였다. 평가 리셋 32개에서 기존과 배치 평가 시간은 13.44초와 1.01초였다. CPU 학습 파라미터는 비트 단위로 일치했고 자연·통제 평가 곡선, AUC, 누적 보상은 10⁻¹² 허용오차에서 일치했다. CUDA 학습에는 CPU 기준 최대 가중치 차이 0.000628이 있었다. 장치 간 부동소수점 차이가 있는 경우 각 장치에서 독립적으로 재현성 검증을 수행하는 것이 맞다. [벤치마크 원자료](evidence/compute_benchmark.json)

Student posterior와 Q 업데이트를 FP64로 100회 갱신했다. 배치 32에서 NumPy CPU 0.009초, CUDA resident 0.294초, 입력 전송 포함 0.570초였다. 배치 256에서는 각각 0.121초, 0.193초, 0.426초였다. CUDA 실험은 해당 갱신 커널을 같은 식으로 작성해 비교한 미세 벤치마크다. 전체 GPU 시뮬레이터의 성능을 추정하는 값은 아니다. [갱신 벤치마크](evidence/learner_updates.json)

여덟 개 단축 학습 작업으로 독립 프로세스 수를 비교했다. 1, 4, 6, 8개 작업자의 총 시간은 각각 10.30, 3.82, 3.27, 2.85초였다. 정규 예산 첫 블록은 작업자 한 개에서 104.42초였다. 그 뒤 같은 실행 디렉터리에서 8개 작업자로 이어서 실행했다. 이 수치는 다른 CPU 연구 작업도 실행 중인 WSL 호스트에서 측정했다. [작업자 비교](evidence/worker_benchmark.json)

CUDA를 사용할 수 있는 실제 호스트에서 집중 회귀 검사 14개를 통과했다. CPU에서 개발 두 블록을 작업자 1개와 2개로 각각 돌렸을 때 두 체크포인트와 두 NPZ 모두 바이트 단위로 일치했다. 결정론적 CPU resume 추가 테스트는 중간 optimizer 및 RNG 상태에서 재시작해 최종 모델이 일치하는지 확인한다.
