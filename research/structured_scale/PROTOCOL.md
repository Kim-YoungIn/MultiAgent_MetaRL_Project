# Structured-game cross-size transfer, protocol v1

Prospective follow-up, specified after the structured-transfer v1 results were opened and before this protocol's final runs. New seed namespaces and games are used. The earlier result did not select this outcome. This local specification is not external registration.

## Task and observations

Use the existing StructuredGame generator and StructuredEnv, four equally frequent motifs with n=3 and memory depth L=3 during training. At evaluation use n=3,L=1; n=3,L=3; and n=6,L=5. Each evaluation game is fresh, with 24 tests per setting in each independent block, six per motif. Corresponding settings use the same game generator seed but need not generate strategically equivalent games. There is no claimed causal effect of changing size or depth. Games and stochasticity follow the actual generator: resource and reciprocity have one public state; sequence has two; mixed has two public plus hidden trust. Only resource and mixed contain stochastic gates. Actions and both rewards are generated by the real simulator, with agents observing their own reward, action history and public states. Policies never observe hidden state, role metadata, rule specifications or opponent rewards.

The learning opponent uses a table indexed by its last joint action, epsilon-greedy Q-learning with alpha=.3, gamma=.8, epsilon=.25, and independently reset parameters. It selects before the simultaneous focal action and updates after every interaction. All outcomes reset the opponent and environment once at the beginning of the task. In particular, checkpoints at k=0,4,8,16 continue the same task state.

## Architecture and training

A candidate-action feature vector consists of one intercept, the first two public state values divided by two with missing slots zero padded, previous own reward, start flag, and three features for each of the five possible history lags: candidate matches own past action, candidate matches opponent's past action, and lag is available. Missing history is padded with zeros. The same feature map applies to every action and is equivariant to relabeling. In the three-action training games, lags 4 and 5 have zero features throughout. In action selection, ties are broken using a shared random permutation sampled independently of action labels. Relabeling the permutation alongside observations gives an equivariant chosen action.

Each game-action pair gets its own linear reward coefficient vector, with shared Gaussian prior N(mu,I) and likelihood N(x·w,1). Estimate mu by marginal-likelihood optimization with a ridge 0.01*||mu||²/2 across the game-action groups. A pooled ridge estimator with the same penalty is fit to the same training observations. One prior vector is shared across action labels, so it applies to unseen action counts. Online posterior ridge regression is initialized independently for each action at the prior mean with covariance I. The adaptive pooled model gets identical posterior updates. Additional models are frozen meta prior, scratch zero-prior with the same online updates, meta with public-state inputs set to zero, and meta with lag 2–5 inputs set to zero. The ablations keep the same originally fitted prior, with masking applied consistently during online updates and queries. Action policies maximize predicted immediate reward myopically, so this experiment measures a limited adaptation mechanism, not sequential optimal control.

Per block collect 32 training games, equally divided across motifs, each 32 turns against the learning opponent. Uniform random focal actions gather identical training data for all priors. No task label or rule identity is input. Fit the prior once per block, then transfer it without refitting to every size/depth setting. A single model copy receives online observations from each test task.

## Evaluation and inference

For each test game execute a shared 16-turn probe with uniform random focal actions. At k=0,4,8,16 evaluate each method against the same true current environment state and current opponent distribution. The one-step payoff for each focal action is the exact expected payoff over the opponent's simultaneous action, computed by the compiled reward kernel checked against the original StructuredEnv. Hypothetical queries do not update either player or the environment. Save complete game specifications, probe records and current opponent distributions, selected actions, action values and learned prior vectors. Also execute each method in a separate fresh 24-turn deployment from the same reset seed, using paired opponent uniforms and independent mutable environment, focal model and opponent. Save actions, rewards, visible state and opponent Q-change magnitude. Stochastic transition streams are seeded identically, but differing actions can consume a different number of transition random draws.

The single prespecified primary endpoint is the paired difference in absolute common-probe expected reward at k=8, meta-adapt minus pooled-adapt, averaged over the n=6,L=5 games and equally across their motifs. It is not a change score. Use 16 independently sampled training catalogs and paired test sets as units, with a two-sided 95% percentile bootstrap interval from 10,000 paired-block resamples using seed 248291. No early stopping or model selection. All other comparisons, including frozen, scratch, feature ablations, depth/size settings and deployment, are descriptive. Save all raw data, seeds, source hashes, fitted coefficients and runtime; resume at complete block boundaries.

Training seed 91827361, development seed 8127, and bootstrap seed 248291 are distinct from all previous protocols. Per-block task seeds and random streams come from deterministic SeedSequence namespaces. Exact spec fingerprints are checked for duplicates within a block and across independent blocks, but action-label and strategic equivalence remain unassessed. This follow-up studies within-generator transfer only, with a hand-selected representation and prior family. Neither larger-scale behavior nor active information acquisition is guaranteed by the design.
